# GNN-DRL-PSO for QoS-Aware Single-Cloud Service Composition

A reproducible research implementation of

**GNN + Deep Reinforcement Learning (PPO) + Discrete Particle Swarm Optimization**

for QoS-aware service composition in a **single-cloud** environment.

Base paper: *"A Hybrid Deep Reinforcement and Swarm Optimization Strategy for
Intelligent Cloud Service Composition."* This project extends the base
DRL-PSO pipeline with a **GNN encoder** that operates on a service
dependency graph.

## 1. Research question

> "Does incorporating GNN-based service-dependency representations into
> a DRL-PSO pipeline improve QoS-aware service composition in a
> single-cloud environment?"

The answer is determined empirically by comparing four ablation
configurations. No conclusion is hard-coded — the interpretation
generated by `evaluation.metrics.interpret_results` reflects the actual
statistical evidence.

## 2. Architecture

```
              Dataset (QWS2.txt, 2507 services)
                        |
              80/20 deterministic split
                        |
              Train partition  ---->  Normalizer + WsRF quartile
                        |
              Service dependency graph
                        |
              GNN encoder (pretrained autoencoder)
                        |
              Actor-critic policy (PPO)
                        |
              Initial composition
                        |
              Discrete PSO refinement
                        |
              QoS fitness  ---->  PPO reward
```

## 3. Dataset

QWS Dataset v2.0 (2507 web services, 9 QoS attributes). Place
`QWS2.txt` at `data/raw/QWS2.txt`.

QWS v2 does NOT ship the `Service Classification` column that v1 did.
This implementation derives it deterministically from the published
WsRF quartile rule; the derivation is fitted on the training partition
only and applied unchanged to the test partition — see
`preprocessing/data_loader.py`.

## 5. Running

```bash
# 1) Inspect + split dataset + fit normalizer
python main.py --stage preprocess

# 2) Pretrain the GNN encoder (autoencoder objective on the training graph)
python main.py --stage train_gnn

# 3) Run the ablation study (all 4 configurations × all seeds in config.yaml)
python main.py --stage ablation

# 4) Or run a specific pair (fast smoke test)
python main.py --stage ablation --configs DRL_PSO GNN_DRL_PSO --seeds 42

# 5) Evaluate a specific trained model on the test partition
python main.py --stage evaluate --name GNN_DRL_PSO --seed 42

# 6) Re-render all figures/tables from existing logs
python main.py --stage report
```

## 6. Configuration

Every parameter lives in `config/config.yaml`. In particular:

- `experiment.seeds`             list of independent seeds (default 5)
- `experiment.num_episodes`      training episodes per seed
- `qos.weights`                  weighted-QoS aggregation (must sum to 1.0)
- `dataset.qos_direction`        `min` (latency, response_time) or `max`
- `gnn.training_mode`            `frozen` | `joint`
- `ablation.configurations`      list of ablation configs to run

## 7. Explanation of components

- **QoS fitness** — normalized weighted aggregation with per-attribute
  aggregation rules (SUM for latency/response_time, MIN for throughput,
  PRODUCT for reliability/availability/successability, MEAN for
  compliance/best_practices/documentation). See `qos/fitness.py`.
- **Service dependency graph** — intra-class kNN + inter-class kNN
  edges built on normalized QoS features. Documented and deterministic.
- **GNN encoder** — 2-layer GraphSAGE by default, pretrained with a
  graph autoencoder objective when `gnn.training_mode == frozen`.
- **PPO** — actor-critic with clipped objective, GAE(λ),
  entropy regularization, gradient clipping. Actor logits are
  `state_repr · service_embeddings.T` so the same architecture applies
  to GNN- and non-GNN- variants inductively.
- **Discrete PSO** — particle = list of service indices (one per
  abstract task). Velocity is a per-slot logit whose sigmoid controls
  the probability of resampling from the candidate pool; when
  triggered, the value is drawn from the current best or the pool.
  This preserves the standard w/c1/c2 semantics while remaining
  syntactically valid for every particle.

## 9. Fairness controls

All four configurations share
- the same 80/20 dataset split,
- the same normalization parameters,
- the same QoS fitness weights and directions,
- the same workflow generator (identical episode seed = seed·10000 + ep),
- the same PPO hyperparameters,
- the same PSO hyperparameters (when in-config),
- the same state MLP / actor projection / critic architecture.
Only the presence of graph-derived service embeddings and PSO
refinement differ between configurations.

## 10. Metrics logged

Per-episode: task sequence, initial composition, final composition,
initial fitness, final fitness, per-attribute normalized QoS,
per-attribute raw aggregation, PSO iteration history, DRL and PSO
seconds, valid-step count.

Aggregate: mean/std per configuration, statistical comparison
(Wilcoxon signed-rank + paired t + Shapiro on differences + Cohen's d
+ 95% CI on Δ), execution-time breakdown, convergence curve.

## 12. Reproducibility

- `numpy`, `python.random`, and `torch` are seeded from every seed
  in `config.experiment.seeds`.
- Workflow episodes are deterministic given `seed * 10000 + episode`.
- The 80/20 split uses `config.dataset.split_seed`.
- All parameters are saved into `results/logs/` alongside metrics so
  that a rerun can be verified byte-for-byte.

## 13. Limitations

- **Service split, not workflow split.** The 80/20 partition splits
  services, not workflows. Both partitions receive their own
  workflow-generation seed so no test workflow was ever seen at
  training time.
- **Non-GNN inductive encoder is a frozen random projection.** This is
  an intentional baseline: no graph structure, but each service still
  receives a deterministic linear encoding of its features.
  A learned projection could close some of the gap and is left as
  future work.
- **GNN uses a graph autoencoder objective.** Alternative
  representation-learning objectives (contrastive, joint with PPO) are
  provided via `gnn.training_mode = joint` for future exploration.
